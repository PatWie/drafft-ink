# drafftink-relay

The blind relay of Drafft.ink's end-to-end encrypted rooms (L1): a sans-IO room core. It takes frames and the time, and it returns frames to send and the time to come back. It reads no payload, links no Loro and no tokio, and never reads a clock.

## For hosts that sleep and hosts with a daily limit

- **Hibernation.** A Durable Object can be evicted while its sockets stay open. The host saves `member_of(conn)` (client id and join order) and the connect time with each socket. On wake it builds a new core over the same stores and calls `restore_member` for each joined socket and `restore_waiting` for each socket that had not joined, then `on_wake`. Restoring sends nothing, reads no store and moves no deadline. `heard(conn, at_ms)` feeds the time of the runtime's last automatic `ping` answer, which never reaches the core, so a quiet but connected member still counts as live for retention. Lost by design: buffered presence, the fill of rate buckets, the `expiring` flag (the first wake works it out again from the stored deadline), the grace after the last close and a pending compaction advice.
- **Daily limit.** A store may fail with `StoreError::DailyLimit` (its capacity is used up until 00:00 UTC). Every refusal then carries `ErrorCode::DailyLimit` with `retry_after_ms = ms_until_utc_midnight(now)`, the image routes answer `ImageStatus::DailyLimit` (503, `daily_limit`) with the same wait, and `Output::quota_hit` tells the host (close with WebSocket code 1013, tell the edge). A failed flush is the one case that is not retried: for an ordinary failure the records stay buffered and the write is tried again after `retry_ms`, but a retry every second until midnight would only burn calls. So on `DailyLimit` the core sends the error to every member, closes every connection (the host goes idle) and drops the unacknowledged buffer. Those records never got an `Ack`, so their senders resend them after they rejoin. A peer that already saw a dropped sequence number rejoins with `last_seq` above the head, and the join serves it as a fresh room. A deletion that hits the limit is tried again after the reset.
- **Codec.** `drafftink_relay::codec` holds the byte layout of the meta, segments and snapshots that the durable stores (files, SQLite, Durable Object storage) share.
