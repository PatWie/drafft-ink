# Review of L3 and L4: canvas, doc, edit, io, collab, drafftink-server

> Note (2026-11-12): the programs `drafftink-cli`, `drafftink-mcp` and `drafftink-server` named here were merged into `drafftink-headless` (and the `drafftink mcp` subcommand) in D18 (`docs/deviations.md`). This document keeps the names of its date.

Scope: `crates/canvas`, `crates/doc`, `crates/edit`, `crates/io`, `crates/collab`, `apps/drafftink-server`, read against
`AGENTS.md` (idiomatic Rust, typed errors, no second copy of a rule, no needless `pub`).

This file lists what was **not** fixed because it is a design change, a public API change in a crate another team
edits, or too large to do safely in a review pass. What was fixed is in the commit log of branch `review-l3-l4`
(summary at the end). Items are ranked by impact. Line numbers are from the branch head.

## Ranked findings

### 1. `edit` does O(scene) work on every pointer move of a transform or an arrow-end drag

**Done** (a)-(c) in perf-a; (d) in d1be7ca: `transform::apply` copies an element only when its points or font change (a move or a turn carries a new `Transform` and nothing else, checked with `scene::validate_transform`).

**Fixed in branch perf-a** (a, b, c below; (d), the clones in `transform::apply`, is open). Gesture frames scan 0 elements; `docs/performance.md` section 7.7 has the numbers, `crates/*/tests/perf_work.rs` the tests.

- `crates/edit/src/transform.rs:417-421` (`prepare`) builds `Relations` (a full pass plus `HashMap` inserts and
  `GroupId`/`ElementId` clones) on every call of `move_by`, `resize`, `rotate`, `set_bounds`, `affine_all`.
  `resize` additionally calls `primaries` twice (`transform.rs:~560`).
- `crates/edit/src/binding.rs:98` `update_bound_arrows` scans every element of the transaction to find arrows bound
  to the changed ids. `transform::apply` calls it on each drag step. `update_bound_arrows_indexed` exists and is
  benchmarked but `transform`, `lifecycle` and `paste` all use the scanning one.
- `crates/edit/src/binding/acquire.rs:116` `find_hovered` iterates `scene.iter()` and resolves every element's
  bind target to pick the shapes near the pointer, on every pointer move while an arrow end is dragged.
- `transform::apply` (`transform.rs:353`, `:183`, `:~300`) clones each moved element up to three times (`olds`,
  `moved`'s `e.clone()`, then `kind` moved into `update`). For a translate of a 1000-point freehand this copies the
  point vector three times per frame.
- Fix: (a) let the transaction expose the committed `DerivedIndex` plus an overlay of the transaction's own changes
  (the doc comment on `Relations` says "a transaction offers no derived index"), or cache `Relations` in the engine
  keyed by `revision()`; (b) make the arrow lookup use `bound_arrows` from the derived index everywhere and keep the
  scan only for arrows bound earlier in the same transaction; (c) give `find_hovered` a candidate source (ids from
  `canvas::SceneIndex::spatial()` around the point) instead of `scene.iter()`; (d) for `Motion::Translate` and
  `Rotate` mutate in place through `tx.update` instead of building `news` copies.

### 2. Copy-as-a-block rule is held twice: `lifecycle::duplicate` and `paste::insert_elements`

**Done in 7b57cfa.** One private `copy` module (`Params`, `build`, `insert`, `CopyError`); `lifecycle::duplicate` and `paste::insert_elements` are thin callers. The group-name rewrite is one function. `text_bind::fresh_element_id` is `unused_element_id` in `ids` and shares the retry loop.
- `crates/edit/src/lifecycle.rs:~363-515` (153 lines) and `crates/edit/src/paste.rs:131-288` (157 lines) do the same
  steps: new ids, regenerate group ids, rebuild each copy (`version = 0`, `deleted = false`, `name = None`, fresh
  seed, offset, remap `group_ids`, `frame_id`, `container_id`, rename the `drafftink.group.*` custom keys), validate,
  pick z keys with a rebalance fallback, insert, `remap_bindings`, `update_bound_arrows`.
  They differ only in where the block goes, which groups survive, and what happens to a label whose container was not
  copied. The group-name `custom` rewrite is implemented twice with different code (`paste.rs:~215`,
  `lifecycle.rs:~437`), so a change to the name key format has to be made in two places.
- Fixed in this pass: the id retry loops (`ids.rs`). Not fixed: the rest.
- Fix: one `copy::Plan` (source elements, `GroupPolicy`, `Placement`, offset) that builds validated copies, and two
  thin callers. `text_bind::fresh_element_id` (`text_bind.rs:625`, 10 000 attempts, returns a used id when exhausted)
  is a third variant of the same retry loop with a different contract; fold it into `ids` too.

### 3. Module names in `edit` follow the engine's command families, not domain concepts

**Done in 7bd48e3 and c56107d.** `element_cmd` is `transform::{CommonBounds, set_common_bounds, tidy}` and `query::hit_by_path`; `selection_cmd` is `group::selection::pick`; `query_cmd` is `query::refs`; `text_cmd` is `text_bind::{font, math, runs, container}` plus `text_bind::create_text`. Tests moved with them (`tests/structure_common_bounds.rs`, `structure_pick.rs`, `text_edit.rs`).
`element_cmd.rs`, `selection_cmd.rs`, `query_cmd.rs`, `text_cmd.rs` are named after `element.*`, `selection.*`,
`query`, `text.*` commands. AGENTS.md says domain rules live in the domain crate under domain names. Suggested homes:
- `element_cmd::set_common_bounds`, `CommonBounds`, `tidy` belong in `transform` (they are `transform::set_bounds`
  for several elements; `merge` is a second `TransformReport` merge). `hit_by_path` belongs in `query` (it is
  `elements_at` along a path).
- `selection_cmd::{pick, pick_group, click_target, keeps_multi_selection, inside_editing_group}` belong in
  `group::selection` next to `click`; the module doc already says `pick` is `click` for a list.
- `query_cmd::{RefQuery, resolve_ref use, all_matches, hit_members}` belong in `query` (a `query::refs` submodule).
- `text_cmd` mixes font steps, colour runs, math sizing and free-text creation; split into `text_bind::runs`,
  `text_bind::font` and `create` (free text creation already exists in `create::text_element`).
Do it together with the engine reviewer: every move is an import change in `crates/engine`.

### 4. Near-identical error enums with the same `NotFound`/`Locked`/`Store`/`NotFinite` variants

**Done in c56107d and 66f3024.** One `TargetError` (`edit::TargetError`) held as the `Target` variant of every error enum (group, selection, transform, lifecycle, frame, z-order, arrange, create, library, text, flowchart, layout, style, query). `impl_from_target!` is gone. The per-enum `code()` methods were unused by the engine and are removed (the engine maps variants to refusal codes; its tests cover the codes); a typed code enum would only have added a second table. Error texts name no command; the engine adds `text.unbind`, `element.delete` and the other advice (`engine/src/cmd/text/support.rs`).
`GroupError`, `SelectionError`, `TransformError`, `LifecycleError`, `FrameError`, `ZOrderError`, `ArrangeError` and
`CreateError` each re-declare `NotFound(ElementId)`, `Locked(Vec<ElementId>)` (with the same `ids_text` message)
and `Store(#[from] StoreError)` (`TextCmdError` has single-id `Missing`/`Locked` variants of its own); `impl_from_target!` (`group/units.rs:44`) papers over it with a
macro. The engine then maps each enum to a refusal code with a hand-written `code()` per enum
(`text_cmd.rs:~133`, `text_bind.rs:~414`, `query.rs:~290`, `layout.rs:~325`, `layout/diagram.rs:~410`,
`flowchart.rs:~67`).
- Fix: `#[error(transparent)] Target(#[from] TargetError)` as one variant, and `Store(#[from] StoreError)` likewise;
  a small `trait Refusable { fn code(&self) -> RefusalCode }` with a typed code enum instead of `&'static str` so a
  typo in a code is a compile error.
- Related: error text in this crate names engine commands (`"Look up ids with element.query or doc.outline."`,
  `text_cmd.rs:~70`). A domain crate should not know command names; let the engine add the hint.

### 5. Stringly-typed error payloads where `Kind` or an enum exists

**Done for the listed items** (c56107d, a3803b4); the rest stays open. `Kind` replaces the kind strings (`Kind` has `Display`, `FromStr`, `ALL`); `TransformError`, `FrameError` and `LayoutError` have a variant per case; `NotRotatableReason`, `Arrangement` and `Gap` are enums; `MathMeasure` returns the typesetter's `MathError` and `TextBindError::InvalidLatex` keeps it with line and column; the `Binding(String)` payloads hold `BindingError`; `io::FormatName` and `io::Expected` replace the format strings; `DocError` has `Malformed`, `BadElement { id, error }`, `BadPeerId`, and `Backend`/`Import` keep the source (`BackendError`); `collab::ConfigError::User` holds `ValidationError`; the server `StoreError::Io` keeps the `io::Error` and has `Timeout { what }`. **Open:** `CreateError::Internal(String)`, `LimitExceeded { what: &'static str }` in `DiagramError`/`ApplyError`, and the server `InvalidRoom`/`Corrupt`/`Backend` strings.
- `kind: &'static str` in `CreateError` (`create.rs:64,74,108,121,140`), `ArrowError` (`arrow.rs:41`),
  `FlowchartError` (`flowchart.rs:40`), `FrameError` (`frame.rs:46`), `LinearError` (`linear.rs:49`),
  `TextBindError` (`text_bind.rs:360,368`), `TextCmdError` (`text_cmd.rs:79,87`). They are filled from
  `Kind::name()`. Store the `Kind` and format it in `Display` (needs `impl Display for Kind` in `scene`).
- `TransformError::BadArgs(&'static str)` (`transform.rs:60`), `FrameError::BadArgs`, `LayoutError::BadGap(&'static str)`:
  each message is a separate case; make them variants.
- `TransformError::NotRotatable { reason: &'static str }` (`transform.rs:56`): the reason is one of two fixed
  strings chosen in `rotate` (`transform.rs:~620`); use a `NotRotatableReason` enum.
- `MathMeasure::math_box -> Result<Size, String>` (`text_cmd.rs:61`) and `TextCmdError::{InvalidLatex(String),
  Frame(String)}` (`:113,:128`): the typesetter's parse error should be a typed `MathError` owned by `typeset` (L1),
  and `Frame` should hold the `FrameError` (`#[from]`).
- `IoError::{Parse, Invalid}::format: &'static str` (`io/src/error.rs:12,36`) and `WrongFormat::expected`: a
  `FormatName` enum (native, excalidraw, library, mermaid, png, svg, legacy) removes typos and lets the UI localise.
- `doc::DocError::{Import(String), Backend(String)}` (`doc/src/error.rs`): `codec::bad()` (`codec.rs:74`) uses
  `Backend` for "this stored element is malformed", which is not what the variant's doc says ("Loro failed in a way
  that is not the caller's fault"). Add `DocError::BadElement { id, reason }` and keep `Backend` for Loro errors;
  a quarantined element is then distinguishable from a library fault. `Backend(e.to_string())` also drops the
  `source()` chain (`LoroError` is not `Clone`/`PartialEq`, which is why); consider `Arc<LoroError>`.
- `collab::ConfigError::User(String)` (`client.rs:86`), `server::StoreError::{InvalidRoom, Io, Corrupt, Backend}(String)`
  (`store/mod.rs:34-42`; `Io` flattens `std::io::Error`, losing `kind()`), `server/room.rs` `store_call` builds
  `StoreError::Io("append timed out")` for a timeout. Add `StoreError::Timeout { what }` and keep the `io::Error`
  (wrap in `Arc` to stay `Clone`).

### 6. Swallowed errors that can hide a bug

**Done in a3803b4.** `LoroStore::with_config` returns `Result` and refuses a reserved peer id with `DocError::BadPeerId`; `version_vector()` and `peer_id()` return `Result` and fail with `Poisoned` (the collab client stops with the reload advice instead of sending an empty vector); `assign_indexes` returns `Result` and `convert` passes it up; `read_element` validates once.
- `doc::LoroStore::with_config` (`doc/src/store.rs:297`): a peer id Loro refuses (`u64::MAX`, reserved) is silently
  replaced by a random one (verified: `peer_id: Some(u64::MAX)` gives `12446503055690562813`). A test or a tool that
  pins a peer id gets a different one without any signal. Either return `Result` (the constructor is infallible only
  by this fallback) or reject the value in `LoroConfig` construction. Documented in this pass, not changed.
- `doc::LoroStore::{version_vector, peer_id, schema_version, undo_depth, can_undo, ...}` (`store.rs:384-520`) map a
  poisoned store to `Vec::new()`, `0`, `SCHEMA_VERSION`, `false`. `version_vector()` returning empty on a poisoned
  store makes a caller send `Join` with "I have nothing", which downloads the whole room into a store that cannot
  take it. Return `Result<_, DocError::Poisoned>` from the ones the sync path uses (`version_vector`, `peer_id`).
- `io::excalidraw::import::assign_indexes` (`import.rs:1145`): `ZIndex::rebalance(n).unwrap_or_default()` returns an
  empty vector on failure, so every element keeps the default index and the document fails later in `validate` with
  a duplicate-index message that does not mention the import. Return `Result<Vec<ZIndex>, IoError>`.
- `doc::codec::read_element` (`codec.rs:~367`): `.err().map(..).unwrap_or_default()` builds the error text from a
  second validation run; compute the error once.

## Bugs found (all four are fixed on branch refactor-l3-l4: items 6 and 11 above)

1. `doc::LoroStore::with_config` silently ignores a refused peer id (item 6). Behaviour documented, not changed.
2. `edit::element_cmd::set_common_bounds` reported `TransformError::NotFinite` when an element vanished between
   `primaries` and `get` (unreachable today, wrong error if it ever happens). Fixed: it reports `NotFound`.
3. `io::excalidraw::import::assign_indexes` failure path (item 6): wrong index vector, error surfaces far from the cause.
4. `server::conn` oversize detection by error text (item 11).

No data-loss or crash bug was found in the sync path (`doc::sync`, `collab::client`, `server::room`); the
hostile-input and convergence tests cover it well.
