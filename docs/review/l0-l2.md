Scope: `crates/geom`, `profile`, `protocol`, `scene`, `sketch`, `typeset`, `render`, read in full against `AGENTS.md`
(idiomatic Rust, typed errors, no second copy of a rule, minimal `pub`, rustdoc, no panics).
Line numbers are those of the branch `review-l0-l2` after the fixes below.

clippy `-D warnings` clean. What is left is mostly design work that changes public types, which other crates use. Those
items are below, ranked by impact. Each says what to change.

### Bug found: element `version` overflow

`scene/src/memory.rs` (commit step) did `f.version = o.version + 1`. A document can carry any `u64` as an element
`version` (validation does not bound it). With `u64::MAX`, the first edit panicked in debug builds and wrapped to 0 in
release builds, and 0 reads as "no version" in `FragmentCache` (`entry.version == e.version && e.version != 0`). It is now
`saturating_add(1)`. The invariant "every change raises the version by one" holds up to `u64::MAX - 1`; at the top the
version stays put, which only affects the render cache of a hostile document. The Loro-backed store in `crates/doc` must
satisfy the same conformance suite; check how it bumps versions (not in this review's scope).

## Larger findings, ranked

### 1. Cache keys list fields by hand, so a new field silently serves stale pictures (high)

- `render/src/hash.rs:92` `paint_hash` writes every paint-relevant field of `Element` one by one, with enums cast as `as u8`.
- `typeset/src/typesetter.rs:115` `feed_text` and `:151` `feed_math` do the same for `TextSpec` and `MathSpec`.
- `sketch/src/key.rs:97` and `:158` do the same for `SketchShape` and `SketchParams`.

Adding a field to `Style`, `TextData`, `TextSpec` and so on compiles without touching the key, and the cache then returns
the old drawing. Today the three keys are complete (the new `render` test checks this for `paint_hash`).

Fix: give the input types `#[derive(Hash)]` and wrap floats in a small `Bits(f64)` newtype that hashes `to_bits()` and
folds `-0.0` into `0.0`. The key code then shrinks to `value.hash(&mut hasher)`, and a new field is covered by the
compiler. The three crates also each have their own 128-bit hasher (`Wide` in render, `digest` in typeset, `KeyBuilder`
in sketch); one shared `Hash128` would remove two.

### 3. `scene::Transform` repeats `geom::ElementFrame` (medium-high; rule held twice)

`scene/src/element.rs:25` `Transform` (x, y, w, h, angle, flip) with `local_to_world` and a private `rotate` (`:69`) is the
same model as `geom/src/transform.rs:29` `ElementFrame` and `Flip` (`:16`), and `scene/src/geom.rs:53` `points_bounds`

`Transform` in one place (`impl From<&Transform> for ElementFrame`) and delete `rotate` and `local_to_world`; change
`points_bounds` to return `Option<Rect>` (callers: `io/src/legacy/build.rs:399`, `io/src/excalidraw/import.rs:611`, `:621`,
`io/src/facts.rs:225`).

### 12. `catch_unwind` around ReX does nothing in the shipped web build (note)

real defence there, as the comment says. Keep both; add a line to `docs/typeset.md` so nobody relies on the catch.
